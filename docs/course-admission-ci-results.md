# 과목 로컬 대기열 CI 검증

검증 실행: https://github.com/skdlzl/class-enrollment/actions/runs/37028005510

검증 대상 기능 코드: `2a73456146928fa53bf4c685d9e5d6e915a85f07`. Windows PowerShell에서 한글이 깨지지 않도록 추가한 UTF-8 BOM은 측정 동작을 변경하지 않습니다.

## 조건

- GitHub-hosted `ubuntu-latest`, Temurin Java 17, MySQL 8.4, Redis 7.4-alpine, JMeter 5.6.3.
- 동일 JAR를 서로 다른 두 JVM에서 8080/8081로 실행. 기능 off/on 비교.
- 매 실행마다 두 JVM 재시작, 20건 예열 후 과목 초기화.
- 500스레드, 5초 ramp-up, 스레드당 1요청. 고유 학생 500명, 과목 1, 정원 100.
- 버전별 3회, 순서 교대. 두 버전 모두 요청별 timing 로그 기록.

각 회차 P95의 산술평균은 10,413.7 → 6,746.7ms(35.2% 감소)입니다. 합친 1,500건의 P95로 표현하지 않습니다. 회차별 평균 응답시간의 평균은 7,146.2 → 5,956.9ms(16.6% 감소)입니다. 503 합계는 95 → 0건입니다. 모든 실행에서 201·신청 내역·enrolled_count가 100으로 일치했습니다.

## 응답 종류별 확인

201 응답의 P95는 기준 버전 6,227/6,246/6,412ms, 개선 후보 6,693/6,316/6,865ms였습니다. 이번 변경으로 201의 P95가 개선됐다고 주장하지 않습니다. 전체 요청의 꼬리 지연 감소와 마감 요청 처리의 개선이 확인된 결과입니다.

409 응답의 P95는 기준 버전 10,250/9,890/10,204ms, 개선 후보 6,933/6,366/6,980ms였습니다.

## 로그 확인

각 실행에서 학생별 마지막 timing 로그 500건을 확인했습니다. 기준 버전의 Redis 과목 락 평균 대기는 5,810/6,190/6,222ms였고 개선 후보는 9/11/10ms였습니다. 대신 로컬 대기 평균은 5,361/5,084/5,324ms였습니다. 따라서 대기가 모두 사라졌다는 설명은 맞지 않습니다. 같은 JVM의 Redis 경합을 제한하고, 마감 확인 후 과목 락 획득을 생략하는 방식으로 전체 P95와 503을 줄였습니다.

단위 및 MySQL/Redis 통합 테스트 29개가 통과했습니다. 결과, 원본 JTL, 오류 응답 본문, 서버 로그는 해당 실행의 `course-admission-evidence` artifact에 있습니다. 측정 종료 후 원래 과목 데이터를 복원했습니다.

이 CI 결과를 기존 Windows 측정값과 섞어 개선율을 계산하지 않습니다. 로컬 비교는 `scripts/measure-course-admission.ps1` 한 번으로 수행합니다.

## 동일 구현 재검증

Windows 한글 표시를 위한 BOM 추가 후 같은 측정 절차를 다시 실행했습니다: https://github.com/skdlzl/class-enrollment/actions/runs/37029210690

| admission-r3 | 5908.6 | 6700 | 100 | 400 | 0 | 100/100 |

P95의 회차 평균은 10,516.3 → 6,485.7ms(38.3% 감소), 503 합계는 71 → 0건입니다. 모든 회차의 201과 DB 두 수치는 100으로 일치했고, 테스트 29개도 통과했습니다. 첫 측정과 재검증은 각각 구분하며 요청을 합친 P95로 표현하지 않습니다.

이후 스크립트의 환경 정보 수집 명령만 `java --version`으로 바꿨습니다. Java 17의 `-version`은 stderr에 출력하므로 Windows PowerShell 5.1의 오류 처리와 충돌할 수 있습니다. `--version`의 stdout 출력을 사용하며 측정 대상 애플리케이션과 부하 조건은 바뀌지 않습니다. 정기 push CI는 1쌍 비교로 측정 절차를 확인하고, 로컬 스크립트 기본값은 버전별 3회입니다.

## 최종 스크립트 확인

이 한 쌍의 P95 감소율은 24.0%입니다. 앞선 3회 측정과 별도로 기록하며, CI 실행에 따라 절대 응답시간과 감소율에 변동이 있음을 확인했습니다. 테스트 29개와 정합성 검증은 통과했습니다.

[Windows PowerShell 5.1 검사](https://github.com/skdlzl/class-enrollment/actions/runs/37030274092)도 통과했습니다. 검사는 스크립트 문법, UTF-8 BOM, java --version 출력 확인을 포함합니다. Windows에서 두 서버와 JMeter를 실행한 실측 결과는 해당 PC의 자동 측정으로 확인합니다.
