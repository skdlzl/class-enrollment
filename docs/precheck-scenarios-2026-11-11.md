# Redis 마감 선차단 시나리오 비교 (2026-11-11)

## 결론
선차단할 마감 요청이 실제로 발생하는 경우 학생 락 진입과 마감 응답 비용이 줄었다.
하지만 성공 신청의 P95는 세 조건 모두 증가했다. 전면 성능 개선으로 주장하지 않는다.
기본값 OFF 유지. 마감 이후의 거절 최적화에는 근거가 생겼지만 항상 켜는 구성을 채택할 근거는 부족하다.
이 기능은 Redis 분산 락이 아니라 Redis 마감 힌트 기반 사전 검사다.

- 조건마다 별도 GitHub runner. 같은 조건 안에서 OFF와 ON을 비교한다.
- 각 조건 3회 × OFF/ON = 총 18회. 순서 OFF→ON / ON→OFF / OFF→ON.
- 앱 2대, 학사/수강 MySQL 2대, Redis 1대. 양쪽 모두 DB 조건부 UPDATE와 학생 DB 락 사용.
- MySQL 각각 1CPU/1GiB, 앱 JVM 최대512MiB, DB별 앱별 연결 풀10, Redis0.5CPU/256MiB.
- 과목 10,000개 고정. 서로 다른 학생 1,000명. 신청 대상은 같은 과목1개, 정원100.
- 모든 학생은 실제 조회해 빈 자리가 있는 과목을 화면에 보관한다. 조회 준비가 모두 끝난 뒤 신청을 시작한다.
- 신청 직전 재조회와 다른 과목 재시도는 하지 않는다. 따라서 정상 결과는 100건 확정과 900건 COURSE_FULL이다.
- 초기 조회 준비는 동시50개로 수행하며 측정 응답 시간은 신청 API 호출 시점부터 센다.
- 매 실행 새 앱 프로세스, 같은 시나리오 1회 예열(제외), 신청 데이터 초기화, 전용 Redis 힌트 초기화.
- Baseline5초 / Mixed15초. 배경 조회 서버당50RPS(학사25+수강25), timeout10초.
- 기존 최신 검색 후 대체 과목 신청 실험과 부하/클라이언트/측정 구간이 다르므로 절대시간을 직접 비교하지 않는다.

## 조건과 생성 정확성
1. hot-5s: 공통 시작2초 뒤부터 1,000명을 5초에 걸쳐 신청. 실제 전송 구간은 양쪽 모두 약4.995초.
2. delayed-click: 공통 시작2초 뒤에 학생별 고정된1~3초 지연을 추가해 2초 폭으로 클릭.
   실제 조회 시점부터의 경과는 3.02~7.46초였다. 따라서 단순히 '조회 후1~3초' 실험이라고 표기하면 안 된다.
   ON의 최대 생성 지연136.45ms, OFF27.44ms. 전송 구간은 양쪽 약2초지만 순간 도착 간격은 차이가 있으므로 정밀 개선율은 제한적으로 해석한다.
3. burst-100ms: 0.1초 폭 목표였으나 실제 전송은 OFF0.439~0.545초, ON0.698~0.941초.
   ON 최대 생성 지연841.69ms. 목표 부하를 달성하지 못했고 구성 간 실제 유입도 달라 성능 우위 판단에서 제외한다.
   정합성 및 선차단 동작 확인용으로만 보존한다.

## 해석
- 인기 과목5초 조건에서 마감 거절P95 약68.7% 감소, 학생 락 진입89.7% 감소를 확인했다.
- 같은 조건 성공 신청P95는16.44→28.41ms로 증가했다. 전체 신청P95도13.60→14.02ms로 줄지 않았다.
- 조회P95 감소는9.06→7.18ms로 약20.8%지만 절대 차이는1.88ms다.
- 지연 클릭에서는 조회P95가 줄었으나 성공/거절P95가 증가했다. 개선과 악화를 함께 보고해야 한다.
- 선차단 후에도 DB 정원 재확인은 수행한다. 따라서 DB 접근이 사라진 것이 아니다.
  수강풀 획득 평균은1752→1855회(5초 조건),1752→2007회(지연 클릭)로 오히려 증가했다.
  줄어든 것은 학생 잠금 및 복잡한 검증과 갱신 시도다.
- 성공 시 Redis 확인과 커밋 후 DB 마감 확인이 추가된다. 이 추가 작업은 코드로 확인되지만
  성공 지연 증가의 정확한 원인별 비중은 이번 계측으로 분리하지 못했다.
- 별도 Redis 없는 DB 사전 조회만으로 비슷한 효과를 낼 수 있는지는 비교하지 않았다.
  따라서 이번 결과로 Redis가 필수이거나 모든 대안보다 우수하다고 주장할 수 없다.
- 이전 최신 조회 실험의 선차단0건 결과도 그대로 유지한다.
- 서버 종료/취소/Redis 장애에 대한 신규 실제 장애 부하 실험은 이번 행렬에 포함하지 않았다.
