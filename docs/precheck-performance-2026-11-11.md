# Redis 마감 선차단 성능 예비 측정 (2026-11-11)

## 결론
이번 부하에서는 선차단 ON의 성능 개선을 확인하지 못했다. 선차단 적중은 3회 합계 0건이었다.
기본값 OFF를 유지한다. 이는 고경합에서의 효과가 없다는 증거가 아니라 이번 조건에서 고경합이 재현되지 않았다는 결과다.

조회 실패와 신청 전송 오류는 없었다. 생성 지연 P95는 1.17~1.51ms, 최대 17.69ms였다.

ON에서 Redis 실패/힌트 갱신 실패 계측도 발생하지 않았다.

## 해석과 한계
1. ON에서도 1500개 요청이 모두 실제 신청 트랜잭션에 진입했다. 마감 힌트로 생략한 요청이 없었다.
2. 검색에서 이미 마감된 과목을 제외하고 이번 환경의 처리 속도가 유입 속도를 충분히 감당했다.
3. ON은 성공 후 마감 확인 SQL이 추가되어 회차당 풀 획득이 정확히 500회 추가되는 패턴이었다
   (OFF 3회차는 재시도 6건으로 별도 차이가 있음). 개선을 기대한 검증 생략은 없었다.
4. 성공 여정 P95는 회차별 방향도 달랐다. 소폭 조회 P95 차이를 개선 성과로 주장하지 않는다.
5. 이번 비교는 선차단 ON/OFF만 비교했다. 이전 비관적 SELECT FOR UPDATE와 조건부 UPDATE의 성능 비교가 아니다.
6. 조건부 UPDATE도 행 잠금을 사용한다. Redis 장애 복구 부하 실험이나 서버 강제 종료 실험은 이번 측정에 포함하지 않았다.
7. 자동 안전성 테스트 25개 통과: 실제 MySQL 조건부 갱신 안전성 9개, 모의 객체 마감 선차단 6개,
   기존 Facade 7개, SET NX Facade 3개.
8. Redis 효과를 추가 검증하려면 별도 고경합 조건이 필요하다. 이번 결과를 버리거나 유리한 회차만 골라 대체하지 않는다.
